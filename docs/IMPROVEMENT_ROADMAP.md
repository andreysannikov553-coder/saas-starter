# IMPROVEMENT ROADMAP

Основан на [PROJECT_AUDIT.md](./PROJECT_AUDIT.md) от 21 сентября 2026.

Порядок фаз — это порядок работ. Внутри фазы задачи упорядочены по зависимостям.
Приоритет: безопасность → стабильность → корректность → архитектура → UX → функциональность → монетизация → оптимизация.

## PHASE 1 — Critical

Цель фазы: проект собирается, деплоится и им можно пользоваться. Без этого всё остальное не имеет смысла.

### 1.1 · Починить сборку

**Что:** привести тип в `prisma.webhookEvent.create` к `Prisma.InputJsonValue`; дать `dashboard/loading.tsx` дефолтный экспорт; заполнить или удалить `spinner.tsx` и `empty-state.tsx`.
**Зачем:** C-01, C-02 — `npm run build` падает, деплой невозможен.
**Файлы:** `src/lib/stripe/webhook.ts`, `src/app/dashboard/loading.tsx`, `src/components/shared/spinner.tsx`, `src/components/shared/empty-state.tsx`.
**Зависимости:** нет. Делается первым.
**Критерий готовности:** `npm run build` завершается успешно; `npm run type-check` чист.

### 1.2 · Починить proxy: публичные маршруты должны быть публичными

**Что:** переписать логику в `lib/supabase/middleware.ts` на явный список публичных префиксов (`/`, `/pricing`, `/login`, `/signup`, `/auth`, `/api/webhooks`) вместо «всё, кроме `/login` и `/auth`». Исключить `/api/webhooks` из matcher в `proxy.ts`.
**Зачем:** C-03 — лендинг, регистрация и вебхук Stripe недоступны. Это ошибка №1 в проекте: она одновременно убивает весь входящий трафик, блокирует регистрацию и ломает биллинг.
**Файлы:** `src/proxy.ts`, `src/lib/supabase/middleware.ts`.
**Зависимости:** нет.
**Критерий готовности:** на собранном приложении анонимные `GET /`, `/pricing`, `/signup`, `/login` отдают 200; `POST /api/webhooks/stripe` доходит до route handler (400 «No signature», а не 307); `GET /dashboard` без сессии отдаёт 307 на `/login`.

### 1.3 · Починить вход, регистрацию и выход

**Что:** вынести `redirect()` из-под `handleServerAction`; перевести формы на `useActionState` с выводом ошибки; учесть случай «email требует подтверждения» (сессии ещё нет — вести на страницу «проверьте почту», а не в дашборд).
**Зачем:** C-04, C-05 — сейчас успешный логин оставляет пользователя на `/login` без единого сообщения.
**Файлы:** `src/lib/actions/auth.ts`, `src/lib/utils/error.ts`, `src/app/login/page.tsx`, `src/app/signup/page.tsx`, новые клиентские формы в `src/components/auth/`.
**Зависимости:** 1.2 (иначе `/signup` недостижим).
**Критерий готовности:** неверный пароль показывает сообщение на форме; успешный вход уводит в `/dashboard`; выход уводит на `/`.

### 1.4 · Синхронизация пользователя Supabase ↔ БД

**Что:** заменить «создать в Supabase, потом create в Prisma» на идемпотентный `upsert`, выполняемый при первом обращении аутентифицированного пользователя (ensure-user), а не в момент регистрации.
**Зачем:** C-06 — сейчас сбой Prisma оставляет пользователя в Supabase Auth без строки в БД, и он навсегда получает «User not found».
**Файлы:** `src/lib/actions/auth.ts`, `src/lib/auth.ts`.
**Зависимости:** 1.3.
**Критерий готовности:** пользователь, созданный в Supabase напрямую (или потерявший строку в БД), при первом входе получает корректную строку; повторный вызов ничего не дублирует.

### 1.5 · Идемпотентный вебхук Stripe

**Что:** сделать `WebhookEvent.id` равным `event.id` от Stripe и отбрасывать повторы; помечать обработанным **конкретное** событие по id, а не `updateMany` по типу; заменить `update` на `updateMany`/`upsert` в `handleSubscriptionDeleted`; всегда возвращать 200 на успешно принятое, но неизвестное событие.
**Зачем:** C-07 — Stripe доставляет at-least-once, сейчас повтор обрабатывается заново, а журнал вебхуков недостоверен.
**Файлы:** `src/lib/stripe/webhook.ts`, `prisma/schema.prisma`, `src/app/api/webhooks/stripe/route.ts`.
**Зависимости:** 1.2 (до вебхука должен доходить запрос).
**Критерий готовности:** повторная доставка одного `event.id` не меняет состояние; пометка «обработано» затрагивает ровно одну строку; удаление подписки несуществующего пользователя не роняет endpoint.

### 1.6 · Валидация Price ID по allow-list

**Что:** перед созданием Checkout-сессии проверять, что `priceId` входит в `PRICING_PLANS`; перенести `STRIPE_PRICE_ID_PRO` / `STRIPE_PRICE_ID_BUSINESS` в `env.mjs` и `env.example`.
**Зачем:** S-01 — сейчас любой залогиненный может оформить подписку по любой цене из нашего Stripe-аккаунта, включая архивную или тестовую за 1 ₽.
**Файлы:** `src/lib/actions/subscription.ts`, `src/lib/stripe/pricing.ts`, `src/env.mjs`, `env.example`.
**Зависимости:** нет.
**Критерий готовности:** чужой/неизвестный `priceId` отклоняется до вызова Stripe.

### 1.7 · Закрыть AI-эндпоинты лимитами и allow-list моделей

**Что:** добавить проверку лимита в `summarizeContent` и `translateText`; заменить `model: z.string()` на `z.enum([...])`; считать расход по фактическим `usage` из ответа OpenAI вместо `text.length / 4`.
**Зачем:** S-02, S-03, S-05 — два эндпоинта сейчас без лимита вообще, модель выбирает пользователь, а эвристика занижает расход на кириллице примерно вдвое.
**Файлы:** `src/lib/actions/ai.ts`, `src/lib/validation/ai.ts`, `src/lib/ai/client.ts`, `src/lib/ai/utils.ts`.
**Зависимости:** нет.
**Критерий готовности:** все четыре action проверяют лимит; неизвестная модель отклоняется валидацией; в `Usage` пишется число из ответа провайдера.

### 1.8 · Security-заголовки

**Что:** заполнить `next.config.ts`: `headers()` с HSTS, `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`; настроить `images.remotePatterns`.
**Зачем:** S-09.
**Файлы:** `next.config.ts`.
**Зависимости:** нет.
**Критерий готовности:** ответ на `GET /` содержит перечисленные заголовки.

### 1.9 · Убрать сырые тексты ошибок из UI

**Что:** в `error.tsx` показывать человеческое сообщение и вызывать `reset()` вместо `router.refresh()`; в `handleServerAction` различать «безопасные» (`AppError`) и внутренние ошибки, наружу отдавать сообщение только для первых.
**Зачем:** S-07 — сейчас наружу уходят тексты ошибок Prisma с именами таблиц и колонок.
**Файлы:** `src/app/error.tsx`, `src/lib/utils/error.ts`, новый `src/app/global-error.tsx`.
**Зависимости:** 1.3 (тот же файл `error.ts`).
**Критерий готовности:** внутренняя ошибка показывает обобщённый текст, подробности идут в лог.

### 1.10 · Вернуть миграции Prisma в git

**Что:** убрать `prisma/migrations/` из `.gitignore`, сгенерировать первую baseline-миграцию.
**Зачем:** S-12 — без истории миграций нельзя воспроизвести схему, откатиться или прогнать её в CI.

**Критерий готовности:** `prisma migrate diff` против пустой БД воспроизводит текущую схему.

## PHASE 4 — AI

**Что:** таймаут на запрос, ретрай с экспоненциальной паузой на 429/5xx, логирование стоимости вызова в разрезе пользователя и модели.

**Зависимости:** 4.1.

### 4.3 · Убрать демо-функциональность шаблона

**Что:** удалить генерацию кода, переводы и саммари вместе с их промптами и валидаторами.

**Файлы:** `src/lib/actions/ai.ts`, `src/lib/ai/prompts/`, `src/lib/validation/ai.ts`.
**Зависимости:** 4.1. **Делать после мержа PR-стека**, чтобы не конфликтовать.
